修复 Windows 下 spawn 子进程（获取 dsh 版本、启动 web 服务、插件 CLI）时弹出黑窗口的问题。

## 根因
Windows GUI 应用无控制台，spawn 控制台子系统子进程时 Windows 会新建控制台窗口，除非设置 `SysProcAttr.CreationFlags = CREATE_NO_WINDOW (0x08000000)`。当前两处 spawn 均未设置：
- `services/dsh.go` `runVersion()`：无 SysProcAttr → 每次版本探测闪黑窗
- `services/proc.go` `RunCli()`：仅 detached 时设 SysProcAttr，且 `proc_windows.go` 的 `detachedSysProcAttr()` 返回 nil → web 服务 / 插件 CLI 弹黑窗，关窗即杀服务

## 改动
1. `services/proc_windows.go`：新增 `spawnProcAttr(detached bool) *syscall.SysProcAttr`，始终返回 `&syscall.SysProcAttr{CreationFlags: 0x08000000}`；删除 `detachedSysProcAttr`
2. `services/proc_unix.go`：新增同名 `spawnProcAttr(detached bool)`，行为与原一致（非 detached 返回 nil，detached 返回 `Setpgid: true`）；删除 `detachedSysProcAttr`
3. `services/proc.go` `RunCli`：`c.SysProcAttr = spawnProcAttr(detached)`（不再仅 detached 分支设置）
4. `services/dsh.go` `runVersion`：补 `c.SysProcAttr = spawnProcAttr(false)`

## 验证
- `go build ./...`
- `GOOS=windows go build ./...`（交叉编译校验 Windows 文件）
- 无前端改动、无导出签名变化 → 不需要 `wails3 generate bindings`；Windows 实际行为由用户自测
