# DSH 插件管理器（utools 插件）实现方案

## 一、总体架构

沿用模板的"preload 隔离 + Vue 前端"架构：Node 侧（`src-utools/src/`）负责文件读写、进程管理、网络请求；前端通过 `window.preload` 访问，业务代码集中在 `@/api` 与 pinia store，页面只做展示。

### 新增 preload 模块（CommonJS，挂到 `window.preload`）

| 模块 | 职责 |
|---|---|
| `src-utools/src/dsh.js` | DSH_HOME 解析（`$DSH_HOME` 回退 `~/\.dsh`）、列出 profiles（含 package.json 的目录）、读写 profile 的 package.json、读写 profile 级 `cordis.patch.yml`、读取某 bundle 自身 `cordis.patch.yml`（解析 insert 行 id）、读取已安装包版本（profiles/\<p>/node_modules 与 profiles/node_modules 两处兜底）、解析/校验 dsh 可执行文件（手动配置路径 → PATH → `~/.bun/bin` 兜底，`dsh --version` 校验） |
| `src-utools/src/process.js` | `spawnStream(cmd, args, {cwd, env})`（流式回调 stdout/stderr/exit，用于安装日志与服务日志）、`kill(pid)`、`isAlive(pid)`、`checkPort(port)`（TCP 探测 127.0.0.1）、`findPidByPort(port)`（lsof） |
| `src-utools/src/net.js`（扩展） | 新增 `httpJson(url, opts)`：node http/https GET/POST、跟随重定向、超时、JSON 解析，用于 npm registry 与 GitHub API |

### 前端新增

- `src/api/dsh.ts`：类型化封装 `window.preload.dsh/process/net`（满足 RL-03 组件不直接触底）
- `src/types/dsh.ts`：Profile / BundleItem / PatchEntry / ServerStatus / DshResolveResult 等类型
- `src/store/dsh/index.ts`：单 store（profiles、当前 profile 详情、dsh 解析状态、服务状态、纯净模式、设置：dsh 路径/端口/主题/语言）
- `src/i18n/`：zh/en 字典 + `useI18n`（语言存 dbStorage，默认跟随系统）
- 路由改造：`/` 重定向到第一个 profile；`/profile/:name`；`/settings`；App.vue 菜单改为「动态 profile 列表 + 设置」组合

## 二、dsh 可执行文件解析与缺失引导（本方案新增重点）

- **解析优先级**：用户在设置里手动配置的路径（dbStorage 持久化）→ PATH 上的 `dsh` → `~/.bun/bin/dsh`（win32 为 `dsh.exe`）→ 未找到。
- **未找到时**：profile 页顶部显示醒目横幅（组件 `DshMissingBanner.vue`）：
  1. 说明文案「未检测到 dsh 命令」；
  2. 安装指引：`bun install -g @deepseek-ai/dsh` 或 `npm install -g @deepseek-ai/dsh`（可复制）；
  3. 下方提供手动输入框（填 dsh 可执行文件路径）+「选择文件」按钮：调用现有 `window.preload.inject.dialog.open({ properties: ['openFile'] })` 选择可执行文件，选中后自动填入输入框。
- **校验与保存**：确认后执行 `dsh --version`（短超时）验证，成功则持久化该路径并在界面显示版本号，失败则提示路径无效。校验结果存 store（`ok / missing / invalid`）。
- 依赖 CLI 的功能（安装/移除/更新/启动 web）在 dsh 缺失时禁用并引导到该横幅；设置页同步提供该字段。
- `dsh plugin add` 内部还需 `pnpm`，若 pnpm 缺失，透传 dsh/pnpm 的 stderr 在安装日志中给出明确提示（dsh 转发器已有友好报错）。

## 三、功能实现对照

### 1. 按 profile 管理插件（合并 bundles + cordis.patch.yml）
- Profile 页加载时：读 `dsh.profile.bundles`（有序、启用态）；解析每个 bundle 自身 patch 的 insert 行得到行 id；读 profile 级 `cordis.patch.yml` 得到 disabled 与 config 覆盖 → 合并出每行的启用状态。
- 列表按「官方（`@deepseek-ai/`）/ 第三方」分组展示，卡片含：拖拽手柄、名称、版本、描述、来源标签（npm/GitHub）、启用开关、操作菜单（配置 / 检查更新 / 更新 / 打开主页 / 移除）。

### 2. 启用 / 禁用（写 cordis.patch.yml）
- 切换开关 → 对该 bundle 所有行 id 写入/删除 `- id: <rowId>\n  disabled: true`（去重、保留用户其他条目）。
- patch 文件用 `yaml` 库解析/序列化，注册 `!!js` 自定义 tag 保证 `!!js` 表达式往返不损坏；重写时保留文件头部注释。

### 3. 添加 / 移除 / 拖拽排序 bundles
- **添加**：走安装搜索流程（见 5），最终执行 `dsh plugin --profile <p> add <spec>`（官方通道，自动 reconcile）。
- **移除**：确认弹窗后执行 `dsh plugin --profile <p> remove <pkg>`；官方包不提供移除。
- **拖拽排序**：HTML5 draggable 排序 → 写回 package.json 的 `dsh.profile.bundles` 顺序（`dsh plugin add` 的 reconcile 只会追加新包、不会打乱既有顺序，安全）。

### 4. 纯净模式
- 开启：对所有第三方 bundle（非 `@deepseek-ai/`）的行 id 写入 disabled 条目。
- 关闭：删除所有属于第三方 bundle 的 disabled 条目（UI 文案注明会一并恢复个别手动禁用的第三方插件）；官方包永不操作。

### 5. 装插件（搜索 npm / GitHub）
- 安装抽屉（`DrawerPlugin` 命令式 + `InstallPluginContent.vue`）：
  - 来源 Tab：**npm**（`registry.npmjs.org/-/v1/search?text=…`，可加 `keywords:dsh-plugin` 预置）与 **GitHub**（`api.github.com/search/repositories?q=topic:dsh-plugin` + 文本搜索）。
  - 结果卡片展示名称/描述/版本/来源，点击「安装」→ 切换到日志视图，流式展示 `dsh plugin add` 输出，成功/失败后刷新列表并通知。
  - 支持粘贴任意 spec（`pkg@ver`、`github:user/repo`、git URL）直接安装。

### 6. 启动 dsh web
- 服务卡片（仅当 profile bundles 含 `@deepseek-ai/dsh-web-app` 时展示，目前即 web）：
  - 状态检测：记录 PID + 端口于 dbStorage；每次进入先探测端口 TCP，结合 `isAlive` 判定「未启动 / 运行中（自身启动）/ 运行中（外部启动）」，外部启动时用 `findPidByPort` 接管以便停止。
  - 启动：`spawnStream('dsh', ['--profile', p, '--port', port])`，detached + unref，日志写入 `$DSH_HOME/plugin-manager/logs/<profile>.log`，可展开查看。
  - 停止：`kill(pid)`（SIGTERM → SIGKILL 兜底）；打开：`shell.openExternal('http://127.0.0.1:<port>')`。
  - 端口可配置（设置页，默认 3080）；启动前校验 dsh 可执行文件已解析。

### 7. 编辑插件 config（JSON）
- 卡片「配置」→ `PluginConfig.tsx` + `PluginConfigContent.vue`（DialogPlugin）：选择该 bundle 的一个行 id，将 profile patch 中该行的 `config` 覆盖层以 JSON 编辑（读取现有覆盖为初始值），保存后 upsert 进 `cordis.patch.yml`。

### 8. 导出 / 导入 profile 视图
- 导出：`dialog.save` + 写 JSON `{profile, bundles[], patches[]}`（含启用态与 config）。
- 导入：`dialog.open` 读文件 → 校验 → 预览弹窗（新增/缺失 bundles 提示）→ 应用写回 package.json 与 cordis.patch.yml；缺失包提示不自动安装。

### 9. 检查更新
- 对 npm 源 bundle 请求 `registry.npmjs.org/<pkg>/latest`（scoped 包做 URL 编码），与已装版本比对，卡片角标提示；「更新」执行 `dsh plugin add <pkg>@latest`。GitHub 源显示「GitHub 源，跳过」。

### 10. 其他（搜索过滤 / 主题 / 语言 / profile 切换）
- **子输入框**：进入 profile 页时 `setSubInput` 过滤插件列表（`onPluginEnter` 的输入文本作为初始过滤词），离开页面 `removeSubInput`。
- **主题**：扩展 `useColorMode` 支持 亮/暗/跟随系统，持久化 dbStorage，`theme-mode` 属性切换 tdesign 暗色。
- **语言**：设置页中英文切换，所有文案走 i18n 字典。

## 五、风险与边界

- dsh / pnpm 缺失时的引导与错误透传见第二部分；非 web profile 无启动服务入口；目前仅 web 一个 profile，代码按多 profile 通用编写。
- patch 编辑只动 profile 级 `cordis.patch.yml`，绝不触碰 `~/.dsh/cordis.patch.yml`（dsh-skin 托管）与各 bundle 自带 patch。
